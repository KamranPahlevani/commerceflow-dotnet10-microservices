## ۱. هدف جلسه

هدف این جلسه ایجاد یک خط مبنای حرفه‌ای برای کل دوره است؛ به‌گونه‌ای که تمام جلسات بعدی روی یک `Repository` تمیز، قابل تکرار، نسخه‌بندی‌شده و قابل بازیابی توسعه داده شوند.

در پایان این جلسه باید موارد زیر برقرار باشند:

- محیط `‎.NET 10` بررسی و تأیید شده باشد.
- تفاوت `SDK`، `Runtime` و `Target Framework` روشن باشد.
- فایل `global.json` در ریشه `Repository` قرار گرفته باشد.
- فایل `CommerceFlow.slnx` در ریشه پروژه ایجاد شده باشد.
- پوشه‌های پایه `src`، `tests` و `docs` ایجاد شده باشند.
- فایل استاندارد `.gitignore` ایجاد و بررسی شده باشد.
- `Git Repository` محلی ایجاد شده باشد.
- شاخه توسعه دوره با نام `Develop` تنظیم شده باشد.
- اولین `Commit` رسمی پروژه ثبت شده باشد.
- `Repository` متناظر در `GitHub` ایجاد و به‌عنوان `origin` متصل شده باشد.
- شاخه `Develop` به `origin/Develop` متصل و `Push` شده باشد.
- جزوه همین جلسه داخل `Repository` قرار گرفته و در پایان برای جلسه `Tag` ایجاد شود.

## ۲. ساختار مفهومی محیط دات‌نت

سه مفهوم زیر نباید با یکدیگر اشتباه گرفته شوند:

```text
Installed SDK
     ↓
Repository SDK Policy
     ↓
Application Target Framework
```

نمونه وضعیت این جلسه:

```text
Installed SDK       : 10.0.101
global.json version : 10.0.101
Target Framework    : net10.0
```

### `SDK`

`SDK` مجموعه ابزارهای لازم برای توسعه، ساخت، تست و انتشار نرم‌افزار است و ابزارهایی مانند موارد زیر را شامل می‌شود:

- `dotnet CLI`
- `MSBuild`
- کامپایلر
- قالب‌های پروژه
- ابزارهای `NuGet`
- ابزارهای `Build`
- ابزارهای `Publish`

### `Runtime`

`Runtime` برای اجرای برنامه استفاده می‌شود.

نمونه‌های مهم:

```text
Microsoft.NETCore.App
Microsoft.AspNetCore.App
Microsoft.WindowsDesktop.App
```

### `Target Framework`

`Target Framework` مشخص می‌کند یک پروژه برای کدام نسخه از پلتفرم هدف‌گذاری شده است.

برای پروژه‌های این دوره:

```xml
<TargetFramework>net10.0</TargetFramework>
```

## ۵. ایجاد و کاربرد فایل `global.json`

فایل `global.json` سیاست انتخاب `SDK` در سطح `Repository` را مشخص می‌کند.

ایجاد فایل:

```powershell
dotnet new globaljson --sdk-version 10.0.101 --roll-forward latestFeature
```

محتوای مورد انتظار:

```json
{
  "sdk": {
    "rollForward": "latestFeature",
    "version": "10.0.101"
  }
}
```

مشاهده فایل:

```powershell
Get-Content .\global.json
```

بررسی اینکه `dotnet` فایل را از ریشه `Repository` شناسایی کرده است:

```powershell
dotnet --info
```

در خروجی باید بخشی مشابه زیر وجود داشته باشد:

```text
global.json file:
D:\Projects\Git\Microservice.Net10\commerceflow-dotnet10-microservices\global.json
```

### دلیل استفاده از `global.json`

استفاده از این فایل باعث می‌شود انتخاب `SDK` برای توسعه‌دهندگان و محیط‌های `CI/CD` کنترل‌شده‌تر و قابل پیش‌بینی‌تر باشد.

گزینه زیر:

```json
"rollForward": "latestFeature"
```

اجازه می‌دهد Resolver در محدوده سیاست تعریف‌شده، نسخه مناسب‌تری از همان خانواده `SDK` را انتخاب کند.

## ۸. ایجاد فایل استاندارد `.gitignore`

```powershell
dotnet new gitignore
```


```powershell
Get-Content .\.gitignore -TotalCount 50
```

```text
[Bb]in/
[Oo]bj/
```

## ۹. نگه‌داشتن پوشه‌های خالی در گیت

`Git` پوشه خالی را ذخیره نمی‌کند.

برای اینکه `src` و `tests` تا زمان ایجاد اولین پروژه در `Repository` باقی بمانند، فایل `.gitkeep` ایجاد می‌کنیم:

```powershell
New-Item .\src\.gitkeep -ItemType File -Force
New-Item .\tests\.gitkeep -ItemType File -Force
```

بررسی:

```powershell
Get-ChildItem .\src -Force
Get-ChildItem .\tests -Force
```

فایل `.gitkeep` قابلیت ویژه‌ای در `Git` ندارد و فقط یک قرارداد رایج برای نگه‌داشتن پوشه خالی است.

## ۱۵. اولین `Push` و تنظیم `Upstream`

ارسال شاخه `Develop` به `GitHub`:

```powershell
git push -u origin Develop
```

گزینه `-u` که معادل `--set-upstream` است، ارتباط زیر را برقرار می‌کند:

```text
Local Develop
      ↓ tracks
origin/Develop
```

پس از آن در دفعات بعد معمولاً کافی است از دستورات ساده زیر استفاده شود:

```powershell
git push
```

```powershell
git pull
```

بررسی `Tracking`:

```powershell
git branch -vv
```

بررسی وضعیت:

```powershell
git status
```

وضعیت مطلوب:

```text
On branch Develop
Your branch is up to date with 'origin/Develop'.

nothing to commit, working tree clean
```

## ۲۰. مرجع کامل دستورات جلسه

```powershell
# Navigate to repository
cd D:\Projects\Git\Microservice.Net10\commerceflow-dotnet10-microservices
Get-Location
dir -Force

# Verify .NET environment
dotnet --version
dotnet --list-sdks
dotnet --list-runtimes
dotnet --info

# Create SDK policy
dotnet new globaljson --sdk-version 10.0.101 --roll-forward latestFeature
Get-Content .\global.json
dotnet --info

# Verify solution
Get-Content .\CommerceFlow.slnx

# Create base directories
New-Item -ItemType Directory -Force -Path .\src
New-Item -ItemType Directory -Force -Path .\tests
New-Item -ItemType Directory -Force -Path .\docs

# Create .gitignore
dotnet new gitignore
dir -Force
Get-Content .\.gitignore -TotalCount 50
Select-String -Path .\.gitignore -Pattern '^\.vs/$','^\[Bb\]in/$','^\[Oo\]bj/$'

# Preserve empty directories
New-Item .\src\.gitkeep -ItemType File -Force
New-Item .\tests\.gitkeep -ItemType File -Force
Get-ChildItem .\src -Force
Get-ChildItem .\tests -Force

# Inspect README
Get-Content .\README.md

# Initialize Git
git init
git branch -M Develop
git symbolic-ref --short HEAD
git branch
git status

# Stage
git add .
git status
git diff --cached --name-status

# First commit
git commit -m "chore(P01-C01-S001): bootstrap repository and .NET 10 solution"
git status
git branch -vv
git log --oneline --decorate -5

# Configure GitHub remote
git remote add origin https://github.com/<username>/commerceflow-dotnet10-microservices.git
git remote -v

# First push
git push -u origin Develop
git branch -vv
git status

# Create session-doc directory
New-Item -ItemType Directory -Force -Path .\docs\sessions\P01

# Stage and commit session booklet
git status
git add .\docs\sessions\P01\P01-C01-S001.md
git diff --cached --name-status
git commit -m "docs(P01-C01-S001): add session 001 learning notes"
git push

# Create and push session tag
git tag -a p01-c01-s001 -m "P01-C01-S001 — .NET 10 Development Environment, Repository & Solution Bootstrap"
git push origin p01-c01-s001
git tag -n
git log --oneline --decorate -5

# Optional: inspect a session checkpoint and return
git checkout p01-c01-s001
git switch Develop
```
