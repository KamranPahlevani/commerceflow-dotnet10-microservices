**Phase:** P01  
**Chapter:** C01

**Project:** <bdi dir="ltr">CommerceFlow</bdi>

## اهداف جلسه

در این جلسه، زیرساخت <bdi dir="ltr">Hosting</bdi> در <bdi dir="ltr">.NET 10</bdi> را از سطح مفهومی تا پیاده‌سازی عملی بررسی می‌کنیم. هدف صرفاً یادگیری چند متد یا API نیست؛ بلکه باید مدل ذهنی درستی از Runtime برنامه، چرخه حیات Application، مدیریت سرویس‌ها، Background Processing، Configuration، Logging و Graceful Shutdown بسازیم.

در پایان جلسه باید بتوانیم این پرسش‌ها را با اطمینان پاسخ دهیم:

- <bdi dir="ltr">Generic Host</bdi> چیست و چه مسئله‌ای را حل می‌کند؟
- تفاوت <bdi dir="ltr">HostApplicationBuilder</bdi>، <bdi dir="ltr">IHost</bdi> و <bdi dir="ltr">RunAsync()</bdi> چیست؟
- تفاوت <bdi dir="ltr">IServiceCollection</bdi> و <bdi dir="ltr">IServiceProvider</bdi> چیست؟
- <bdi dir="ltr">IHostedService</bdi>، <bdi dir="ltr">BackgroundService</bdi> و <bdi dir="ltr">IHostedLifecycleService</bdi> چه تفاوتی دارند؟
- <bdi dir="ltr">CancellationToken</bdi> چگونه با Graceful Shutdown مرتبط است؟
- چرا یک <bdi dir="ltr">BackgroundService</bdi> نباید مستقیماً یک Dependency از نوع <bdi dir="ltr">Scoped</bdi> را Capture کند؟
- نقش <bdi dir="ltr">IServiceScopeFactory</bdi> چیست؟
- <bdi dir="ltr">IHostApplicationLifetime</bdi> چه اطلاعات و قابلیت‌هایی در اختیار ما قرار می‌دهد؟
- <bdi dir="ltr">IHostEnvironment</bdi> چگونه Environment برنامه را مشخص می‌کند؟
- تفاوت <bdi dir="ltr">Host Configuration</bdi> و <bdi dir="ltr">Application Configuration</bdi> چیست؟
- ترتیب Override شدن Configuration Sources چگونه است؟
- <bdi dir="ltr">Host.CreateApplicationBuilder(args)</bdi> چه Defaults مهمی را برای ما Bootstrapping می‌کند؟

# 1. مسئله‌ای که Generic Host حل می‌کند

یک Console Application ساده می‌تواند فقط با چند خط اجرا شود:

```csharp
Console.WriteLine("CommerceFlow started.");
```

اما یک Application واقعی معمولاً به این زیرساخت‌ها نیاز دارد:

```text
Dependency Injection
Configuration
Logging
Application Lifetime
Graceful Shutdown
Hosted Services
Environment
Background Processing
```

اگر هرکدام از این زیرساخت‌ها را به‌صورت دستی و مستقل ایجاد کنیم، خیلی زود با کدی پراکنده، وابستگی‌های نامنظم و Lifecycle نامشخص مواجه می‌شویم.

<bdi dir="ltr">Generic Host</bdi> یک Runtime Container استاندارد برای Application فراهم می‌کند:

```text
Operating System
      │
      ▼
┌───────────────────────────────┐
│         .NET Generic Host     │
│                               │
│  Dependency Injection         │
│  Configuration                │
│  Logging                      │
│  Environment                  │
│  Application Lifetime         │
│  Hosted Services              │
│  Graceful Shutdown            │
│                               │
└───────────────┬───────────────┘
                │
                ▼
        Application Code
```

نکته مهم:

> <bdi dir="ltr">Generic Host</bdi> خود Business Application نیست؛ بستری است که Application درون آن ساخته، اجرا و متوقف می‌شود.

همین Runtime Model بعداً در <bdi dir="ltr">Worker Service</bdi>، <bdi dir="ltr">RabbitMQ Consumer</bdi>، <bdi dir="ltr">Outbox Processor</bdi> و بسیاری از اجزای Microserviceها استفاده خواهد شد.

# 4. اولین Generic Host

نسخه پایه `Program.cs`:

```csharp
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Logging;

HostApplicationBuilder builder =
    Host.CreateApplicationBuilder(args);

builder.Services.AddHostedService<HostLifecycleService>();

IHost host = builder.Build();

IHostApplicationLifetime lifetime =
    host.Services.GetRequiredService<IHostApplicationLifetime>();

ILogger logger =
    host.Services
        .GetRequiredService<ILoggerFactory>()
        .CreateLogger("CommerceFlow.Hosting");

lifetime.ApplicationStarted.Register(() =>
{
    logger.LogInformation(
        "Application started callback.");
});

lifetime.ApplicationStopping.Register(() =>
{
    logger.LogInformation(
        "Application stopping callback.");
});

lifetime.ApplicationStopped.Register(() =>
{
    logger.LogInformation(
        "Application stopped callback.");
});

await host.RunAsync();
```

سه مرحله اصلی را باید از هم جدا نگه داریم:

```text
CreateApplicationBuilder
        │
        ▼
Configure Application
        │
        ▼
Build
        │
        ▼
Runtime Host
        │
        ▼
RunAsync
```

# 5. Builder چیست؟

این خط:

```csharp
HostApplicationBuilder builder =
    Host.CreateApplicationBuilder(args);
```

هنوز Application را اجرا نمی‌کند.

`builder` را می‌توان Recipe یا Definition برنامه در نظر گرفت.

در این مرحله کارهایی مانند موارد زیر انجام می‌شود:

```csharp
builder.Services.AddSingleton<SomeService>();

builder.Services.AddScoped<SomeScopedService>();

builder.Configuration["SomeKey"];

builder.Logging.AddConsole();
```

بنابراین:

```text
Builder = Configuration Phase
```

در این مرحله Dependencyها ثبت می‌شوند، Logging و Configuration تنظیم می‌شوند و Environment قابل بررسی است.

---

# 6. IServiceCollection چیست؟

این Property:

```csharp
builder.Services
```

از نوع:

```csharp
IServiceCollection
```

است.

`IServiceCollection` را باید مجموعه Registrationهای DI بدانیم:

```text
IServiceCollection

Service A → Implementation A
Service B → Implementation B
IHostedService → HostLifecycleService
...
```

مثلاً:

```csharp
builder.Services.AddHostedService<HostLifecycleService>();
```

به معنای ساخت فوری `HostLifecycleService` نیست.

فقط Registration انجام شده است.

قاعده مهم:

```text
Register ≠ Instantiate
```

وقتی می‌نویسیم:

```csharp
IHost host = builder.Build();
```

تعریف Application به Runtime Host تبدیل می‌شود.

مدل ذهنی:

```text
HostApplicationBuilder
        │
        │ Build()

┌──────────────────────────────┐
│            IHost             │
│                              │
```

بعد از `Build()` می‌توان از:


استفاده کرد.

نوع `host.Services`:

```csharp
IServiceProvider
```

است.

# 8. IServiceCollection vs IServiceProvider

این تفکیک بنیادی است.

قبل از Build:

```csharp
builder.Services
```

یعنی:

```text
IServiceCollection
→ Registration
```

بعد از Build:

```csharp
host.Services
```

یعنی:

```text
IServiceProvider
→ Resolution
```

مدل کامل:

```text
IServiceCollection
        │
        │ registrations
        ▼
      Build()
        │
        ▼
IServiceProvider
        │
        │ resolves
        ▼
      Instances
```

برای مثال:

```csharp
IHostApplicationLifetime lifetime =
    host.Services
        .GetRequiredService<IHostApplicationLifetime>();
```

در اینجا دیگر سرویسی ثبت نمی‌شود؛ بلکه Instance مربوط به یک Service از Container Resolve می‌شود.

# 9. اولین IHostedService

فایل `HostLifecycleService.cs`:

```csharp
using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Logging;

public sealed class HostLifecycleService : IHostedService
{
    private readonly ILogger<HostLifecycleService> _logger;

    public HostLifecycleService(
        ILogger<HostLifecycleService> logger)
    {
        _logger = logger;

        _logger.LogInformation(
            "HostLifecycleService constructor.");
    }

    public Task StartAsync(
        CancellationToken cancellationToken)
    {
        _logger.LogInformation(
            "HostLifecycleService StartAsync.");

        return Task.CompletedTask;
    }

    public Task StopAsync(
        CancellationToken cancellationToken)
    {
        _logger.LogInformation(
            "HostLifecycleService StopAsync.");

        return Task.CompletedTask;
    }
}
```

Contract اصلی `IHostedService`:

```csharp
Task StartAsync(
    CancellationToken cancellationToken);

Task StopAsync(
    CancellationToken cancellationToken);
```

مدل Lifecycle:

```text
Construct
   ↓
StartAsync
   ↓
Application Running
   ↓
StopAsync
```

Host مسئول فراخوانی این متدهاست.

# 11. خط اول Log از کجا می‌آید؟

وقتی می‌نویسیم:

```csharp
_logger.LogInformation(
    "Hosted service is starting.");
```

ممکن است Console چنین خروجی بدهد:

```text
info: HostLifecycleService[0]
      Hosted service is starting.
```

ساختار:

```text
info: HostLifecycleService[0]
│     │                   │
│     │                   └── EventId
│     └────────────────────── Category
└──────────────────────────── LogLevel
```

`info` از متد:

```csharp
LogInformation(...)
```

می‌آید.

`HostLifecycleService` از Generic Type این Logger می‌آید:

```csharp
ILogger<HostLifecycleService>
```

و `[0]` مقدار Default مربوط به `EventId` است.

مثلاً:

```csharp
_logger.LogInformation(
    new EventId(1001, "ServiceStarting"),
    "Hosted service is starting.");
```

می‌تواند Event ID مشخصی داشته باشد.

نکته اصلی:

> ما `Console.WriteLine` نکرده‌ایم؛ `Console Logger Provider` پیام را Format و چاپ کرده است.

# 12. چرا ILogger<T> بدون Registration دستی کار می‌کند؟

علت:

است.

```text
   ▼

   │
```

کلاس Application فقط با `ILogger<T>` کار می‌کند و Destination نهایی Log را نمی‌شناسد.

# 15. Graceful Shutdown

Graceful Shutdown یعنی Application به‌جای Kill شدن ناگهانی، فرصت پیدا کند Resourceهای خود را به‌صورت کنترل‌شده آزاد کند.

مثلاً در یک Consumer:

```text
Stop receiving new messages
        ↓
Finish current message
        ↓
Commit transaction
        ↓
Close broker connection
        ↓
Dispose scoped resources
        ↓
Exit process
```

در Console، معمولاً:

```text
Ctrl+C
```

باعث شروع Shutdown می‌شود.

در Container یا Linux، Signalهایی مانند:

```text
SIGTERM
```

می‌توانند Shutdown Host را آغاز کنند.

برای درخواست Shutdown کنترل‌شده از داخل Application:

```csharp
lifetime.StopApplication();
```

از `Environment.Exit(...)` برای Lifecycle عادی Host استفاده نمی‌کنیم.

# 17. HeartbeatWorker

فایل `HeartbeatWorker.cs`:

```csharp
using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Logging;

public sealed class HeartbeatWorker : BackgroundService
{
    private readonly ILogger<HeartbeatWorker> _logger;

    public HeartbeatWorker(
        ILogger<HeartbeatWorker> logger)
    {
        _logger = logger;

        _logger.LogInformation(
            "HeartbeatWorker constructor.");
    }

    protected override async Task ExecuteAsync(
        CancellationToken stoppingToken)
    {
        _logger.LogInformation(
            "HeartbeatWorker ExecuteAsync started.");

        try
        {
            while (!stoppingToken.IsCancellationRequested)
            {
                _logger.LogInformation(
                    "Heartbeat at {CurrentTime}",
                    DateTimeOffset.Now);

                await Task.Delay(
                    TimeSpan.FromSeconds(2),
                    stoppingToken);
            }
        }
        catch (OperationCanceledException)
            when (stoppingToken.IsCancellationRequested)
        {
            _logger.LogInformation(
                "HeartbeatWorker cancellation requested.");
        }

        _logger.LogInformation(
            "HeartbeatWorker ExecuteAsync completed.");
    }

    public override async Task StopAsync(
        CancellationToken cancellationToken)
    {
        _logger.LogInformation(
            "HeartbeatWorker StopAsync started.");

        await base.StopAsync(cancellationToken);

        _logger.LogInformation(
            "HeartbeatWorker StopAsync completed.");
    }
}
```

ثبت:

```csharp
builder.Services.AddHostedService<HeartbeatWorker>();
```

# 18. ExecuteAsync چه چیزی را نمایش می‌دهد؟

Task برگشتی از:

```csharp
ExecuteAsync(...)
```

نماینده Long-running Operation است.

مدل:

```text
ExecuteAsync starts
       │
       ▼
while loop
       │
       ├── work
       ├── work
       ├── work
       └── ...
       │
       ▼
Cancellation requested
       │
       ▼
ExecuteAsync completes
```

# 19. چرا Loop را داخل StartAsync نمی‌گذاریم؟

این الگو اشتباه است:

```csharp
public async Task StartAsync(
    CancellationToken cancellationToken)
{
    while (true)
    {
        await DoWorkAsync();
    }
}
```

چون `StartAsync()` Complete نمی‌شود و Startup Host را با Runtime Work مخلوط می‌کند.

مدل بهتر:

```text
StartAsync
   ↓
Startup work
   ↓
Return
```

در مقابل:

```text
ExecuteAsync
   ↓
Long-running work
   ↓
Completes on shutdown
```

# 20. تغییر مهم BackgroundService در .NET 10

در نسخه‌های قبل از `.NET 10`، بخش Synchronous ابتدای `ExecuteAsync()` تا قبل از اولین `await` می‌توانست روی Thread مربوط به Startup اجرا شود و شروع سرویس‌های دیگر را Block کند.

در `.NET 10`:

> کل `ExecuteAsync()` به‌صورت Background Task اجرا می‌شود و هیچ بخش ابتدایی آن برای Block کردن Startup سایر Serviceها قابل اتکا نیست.

مدل جدید:

```text
.NET 10

ExecuteAsync
     │
     ▼
Entire method runs as
background work
```

اگر Initialization باید واقعاً Startup را Block کند، گزینه‌های مناسب‌تر عبارت‌اند از:

```text
Constructor
StartAsync override
IHostedLifecycleService
Custom IHostedService
```

این تغییر یک Behavioral Change مهم در `.NET 10` است.

# 21. CancellationToken در Worker

پارامتر:

```csharp
CancellationToken stoppingToken
```

رابط Worker با Shutdown Host است.

وقتی Stop شروع می‌شود، Token Cancel می‌شود.

مدل:

```text

     │
     ▼
stoppingToken canceled
     │
     ▼
Worker notices cancellation
     │
     ▼
ExecuteAsync finishes
```

# 22. Propagate کردن CancellationToken

فقط این شرط کافی نیست:

```csharp
while (!stoppingToken.IsCancellationRequested)
```

Token را باید به Async Operationها هم منتقل کنیم:

```csharp
await Task.Delay(
    TimeSpan.FromSeconds(2),
    stoppingToken);
```

همین اصل در APIهای دیگر:

```csharp
await dbContext.SaveChangesAsync(
    stoppingToken);
```

```csharp
await httpClient.SendAsync(
    request,
    stoppingToken);
```

```csharp
await channel.Reader.ReadAsync(
    stoppingToken);
```

قاعده:

> `CancellationToken` باید تا جای ممکن در Call Chain پایین برده شود.

# 23. Cancellation شکست نیست

وقتی:

```csharp
Task.Delay(..., stoppingToken)
```

Cancel شود، ممکن است:

```text
OperationCanceledException
```

یا:

```text
TaskCanceledException
```

مشاهده شود.

در Shutdown کنترل‌شده:

```text
Cancellation ≠ Failure
```

برای Handle کردن Cancellation مورد انتظار:

```csharp

    when (stoppingToken.IsCancellationRequested)
{
    _logger.LogInformation(
        "Worker cancellation requested.");
}
```

این Filter باعث می‌شود فقط Cancellation مرتبط با Stop طبیعی Worker Handle شود.

# 29. ScopedWorker

```csharp
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Logging;

public sealed class ScopedWorker : BackgroundService
{
    private readonly IServiceScopeFactory _scopeFactory;
    private readonly ILogger<ScopedWorker> _logger;

    public ScopedWorker(
        IServiceScopeFactory scopeFactory,
        ILogger<ScopedWorker> logger)
    {
        _scopeFactory = scopeFactory;
        _logger = logger;
    }

    protected override async Task ExecuteAsync(
        CancellationToken stoppingToken)
    {
        _logger.LogInformation(
            "ScopedWorker started.");

        try
        {
            while (!stoppingToken.IsCancellationRequested)
            {
                await using AsyncServiceScope scope =
                    _scopeFactory.CreateAsyncScope();

                IScopedProcessingService processingService =
                    scope.ServiceProvider
                        .GetRequiredService<IScopedProcessingService>();

                await processingService.ProcessAsync(
                    stoppingToken);

                await Task.Delay(
                    TimeSpan.FromSeconds(2),
                    stoppingToken);
            }
        }
        catch (OperationCanceledException)
            when (stoppingToken.IsCancellationRequested)
        {
            _logger.LogInformation(
                "ScopedWorker cancellation requested.");
        }

        _logger.LogInformation(
            "ScopedWorker completed.");
    }
}
```

ثبت:

```csharp
builder.Services.AddHostedService<ScopedWorker>();
```

# 62. مهم‌ترین نکات جلسه

- <bdi dir="ltr">Generic Host</bdi> Runtime Infrastructure استاندارد Application را فراهم می‌کند.
- <bdi dir="ltr">HostApplicationBuilder</bdi> مربوط به مرحله Configuration و Composition است.
- <bdi dir="ltr">IServiceCollection</bdi> برای Registration و <bdi dir="ltr">IServiceProvider</bdi> برای Resolution است.
- `Build()` Host Runtime را می‌سازد؛ `RunAsync()` Lifecycle آن را اجرا می‌کند.
- <bdi dir="ltr">IHostedService</bdi> Contract پایه Start/Stop است.
- <bdi dir="ltr">BackgroundService</bdi> abstraction مناسب‌تری برای Long-running Work است.
- در `.NET 10` کل `ExecuteAsync()` به‌عنوان Background Task اجرا می‌شود.
- `CancellationToken` باید در Async Call Chain جریان پیدا کند.
- Hosted Service یک Singleton است و Scoped Dependency نباید مستقیم در آن Capture شود.
- <bdi dir="ltr">IServiceScopeFactory</bdi> امکان ایجاد Scopeهای کوتاه‌عمر در Worker را می‌دهد.
- <bdi dir="ltr">IHostedLifecycleService</bdi> Hookهای دقیق‌تری برای Lifecycle یک Service فراهم می‌کند.
- <bdi dir="ltr">IHostApplicationLifetime</bdi> Lifetime کل Application را نمایش می‌دهد.
- <bdi dir="ltr">IHostEnvironment</bdi> Environment، Application Name و Content Root را در اختیار برنامه می‌گذارد.
- Environment و Configuration دو مفهوم مستقل ولی مرتبط هستند.
- `CreateApplicationBuilder` Configuration، Logging، DI و Environment Defaults را Bootstrapping می‌کند.
- Graceful Shutdown برای Reliability در Workerها و Microserviceها یک Requirement واقعی است، نه یک قابلیت تزئینی.
